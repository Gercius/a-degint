# F2 — Wind Direction Overlay: Feature Plan

---

## Overview

Fetch live wind data from Open-Meteo and render it visually on the village map — directional arrows spread across the visible map area, a status bar showing current speed/direction, and auto-refresh every 10 minutes. Wind responses are cached in `localStorage` for the refresh window, and the same live wind data now also feeds later smoke/downwind behavior.

---

## Phase 1 — Wind Data Service

**Goal:** Typed, validated wind data fetching with Zod, timestamped results, and safe error handling — no UI yet.

- [x] **1.1** Create `src/services/wind.ts` — the sole place responsible for fetching wind data
- [x] **1.2** Define a `WindData` Zod schema validating `wind_speed_10m` (number) and `wind_direction_10m` (number) from the `current` block of the Open-Meteo response
- [x] **1.3** Export the inferred TypeScript type: `type WindData = z.infer<typeof WindDataSchema>`
- [x] **1.4** Write `fetchWindData(signal?): Promise<{ data: WindData; timestamp: number }>` — builds the Open-Meteo URL from `VILLAGE_CENTER` coords, fetches, parses with `.json()`, validates with Zod `.parse()`, and returns typed data plus fetch timestamp
- [x] **1.5** Add error wrapping: catch Zod validation errors and network errors separately, re-throw as a typed `WindFetchError`, while letting `AbortError` pass through for request cancellation
- [x] **1.6** Remove temporary browser-console verification code after confirming real data comes back with the correct shape
- [x] **1.7** Cache successful wind responses in `localStorage` using a village-specific key, and treat cached data as fresh for up to `WIND_REFRESH_INTERVAL_MS`

## Phase 3 — `useWind` Hook

**Goal:** Encapsulate fetch state and polling logic in a reusable hook, with imperative refresh support kept internal for now.

- [x] **3.1** Create `src/hooks/use-wind.ts`
- [x] **3.2** Define hook return shape: `{ wind: WindData | null, status: 'idle' | 'loading' | 'success' | 'error', error: string | null, lastUpdated: Date | null, refresh: () => void }`
- [x] **3.3** Implement initial fetch on mount using `useEffect`
- [x] **3.4** Implement `setInterval` polling every `WIND_REFRESH_INTERVAL_MS` — clear interval on unmount
- [x] **3.5** Expose a `refresh()` callback that triggers an immediate re-fetch; UI wiring for manual refresh is optional
- [x] **3.6** Handle loading state: set `status = 'loading'` before fetch, `'success'` or `'error'` after
- [x] **3.7** On successful fetch, update `lastUpdated` from the fetch result timestamp so cached responses still show an accurate freshness time
- [x] **3.8** Use `AbortController` inside the hook so in-flight requests are cancelled before a new refresh or on unmount

## Phase 5 — Wind Arrow Utilities

**Goal:** Pure functions that compute arrow positions and rotation — no Leaflet dependency, fully unit-testable.

- [x] **5.1** Create `src/utils/wind-arrows.ts`
- [x] **5.2** Write `generateArrowGrid(bounds: LatLngBounds, cols: number, rows: number): LatLng[]` — divides the bounding box into an evenly-spaced grid and returns center points for each cell
- [x] **5.3** Write `windDegToArrowRotation(deg: number): number` — converts meteorological wind direction (where wind is *coming from*) to a CSS/SVG rotation angle (where arrow points *toward*)
  - Meteorological 0° = wind from North = arrow points South = 180° rotation
  - Formula: `(deg + 180) % 360`
- [x] **5.4** Write `windSpeedToArrowScale(speed: number): number` — maps m/s to a visual scale multiplier (e.g. clamp between 0.6–1.4) for subtle size variation
- [x] **5.5** Manually verify `windDegToArrowRotation` with a few cases: 0° → 180°, 90° (East wind) → 270°, 270° (West wind) → 90°

- [x] **6.6** For each position, render a `<Marker>` with a custom `DivIcon` containing an SVG arrow element
- [x] **6.7** SVG arrow design: simple chevron or filled triangle — clean, readable at all zoom levels
- [x] **6.8** Apply `windDegToArrowRotation()` as a CSS `transform: rotate(Xdeg)` on the SVG element
- [x] **6.9** Apply `windSpeedToArrowScale()` as a CSS `transform: scale(X)` combined with rotation
- [x] **6.10** Pass `interactive={false}` to markers so they don't interfere with map clicks/panning

## Definition of Done

- Live wind speed and direction displayed in the status bar in human-readable form
- Directional arrows spread evenly across the map pointing downwind
- Arrows rotate correctly and smoothly when data updates
- Auto-refresh fires every 10 minutes; successful responses are cached locally for that freshness window; manual refresh remains optional
- Error state is non-blocking — last known data remains visible
- No race conditions on rapid refresh
- Zero console errors; F1 features unaffected
