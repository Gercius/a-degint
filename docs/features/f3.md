# F3 — List Potentially Hit Homes: Feature Plan

---

## Overview

Let the user select their home address from the village building data, then calculate which neighboring buildings fall downwind based on live wind data — showing a clear, human-readable warning if smoke could reach neighbors and highlighting affected buildings on the map.

No automated pass/fail verdict is given — the app informs, the user decides.

## Phase 2 — Downwind Calculation Utilities

**Goal:** Pure, testable functions that determine which buildings are in the downwind cone from a given origin, with wind-speed-based plume behavior.

- [x] **2.1** Create `src/utils/downwind.ts`
- [x] **2.2** Write `getBearing(from: LatLng, to: LatLng): number` — returns compass bearing in degrees (0–360) from one point to another using the haversine bearing formula
- [x] **2.3** Write `getDistance(from: LatLng, to: LatLng): number` — returns distance in meters between two points (haversine)
- [x] **2.4** Write `isInDownwindCone(origin: LatLng, target: LatLng, windDirection: number, coneAngle: number, maxDistanceM: number): boolean`:
    - Computes bearing from `origin` to `target`
    - Computes angular delta between that bearing and the downwind direction (`(windDirection + 180) % 360`)
    - Returns `true` if delta ≤ `coneAngle / 2` AND distance ≤ `maxDistanceM`
- [x] **2.5** Add wind-profile logic in `src/config/wind.ts` via `getDownwindProfile(windSpeedMs)`:
    - very low wind disables directional downwind logic
    - stronger wind narrows the cone and extends the max distance
    - weaker wind widens the cone and shortens the max distance
- [x] **2.6** Write `getDownwindBuildings(origin: Building, allBuildings: Building[], windDirection: number, windSpeedMs: number): Building[]` — filters all buildings using `isInDownwindCone`, excludes the origin building itself, and returns a sorted result
- [x] **2.7** Add manual verification coverage in `src/utils/downwind.test.ts` for bearing, distance, cone membership, and filtered downwind results

## Definition of Done

- User can search and select their home address from a combobox; selection persists on reload
- When wind data is available, a clear warning explains whether neighboring buildings may be affected
- When no neighbors are at risk, a neutral/green message confirms it's likely safe
- No false warning is shown while wind data is still loading, errored, or too calm for directional logic
- Home pin is visible on the map at the selected building's location
- Potentially affected buildings are highlighted in red and the smoke cone is drawn when directional wind logic is active
- Control panel doesn't overlap existing UI elements at any viewport size
- Downwind results update automatically on wind refresh — no stale data
- F1 and F2 features fully unaffected
